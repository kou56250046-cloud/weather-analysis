# weather-analysis

7つの数値予報モデルを合議し、過去の予報と実測から統計補正を学習した天気予報。
予報の隣に、その予報が過去どれだけ外したかを必ず出す。
あわせて 1940 年以降の気象データを分析する。

完全個人・無料運用。npm 依存ゼロ。PWA なのでホーム画面に置いてオフラインでも見られる。

**https://kou56250046-cloud.github.io/weather-analysis/**

---

## 何をしているか

天気アプリの弱点は、予報そのものの質ではなく見せ方と検証の欠如にある。
単一ソースの決定値しか出さず、地点固有の癖を補正せず、外した実績を開示しない。

ここに3つの手を入れている。

1. **合議** ECMWF / GFS / ICON / JMA / UKMO / GEM / Météo-France の7モデルを同時に取る
2. **統計補正（MOS）** 過去の予報と実測から回帰を学習し、地点別・リードタイム別の系統誤差を消す
3. **精度の開示** 予報と同じ画面に、前向き検証で測った実績誤差を出す

### 実測した効果（東京都世田谷区・最高気温・前向き検証 925日）

| 何日先 | 自作の合議 | 7モデルの単純平均 | 最も当たる単独モデル | 気象庁モデル単独 |
|---|---|---|---|---|
| 1日 | **0.80℃** | 1.39℃ | 1.29℃ (ICON) | 1.93℃ |
| 3日 | **1.10℃** | 1.64℃ | 1.55℃ (ICON) | 2.26℃ |
| 7日 | **1.83℃** | 2.27℃ | 2.26℃ (GFS) | 2.73℃ |

平均絶対誤差。すべて、その日より前のデータだけで学習した係数で採点している。

7日先でも 1.83℃ 外す。補正をかけても 9.9℃ 外した日がある。
これを隠さず出すのがこのシステムの主眼で、精度そのものは副産物に近い。

## 使い方

```bash
node scripts/serve.js        # http://localhost:8790 で画面を開く（8787 は AI Radar が使う）
npm test                     # 単体テスト
npm run icons                # PWA のアイコンを描き直す
```

`file://` での直接オープンには対応していない。データを `fetch` で読むため。

### ホーム画面に置く

Android と デスクトップの Chrome では、開いてしばらくすると画面上部に追加の案内が出る。
iOS の Safari は共有メニューから「ホーム画面に追加」を選ぶ。

追加すると、アドレスバーの無いアプリとして開き、圏外でも最後に見たデータを表示する。
繋がっているときは必ず最新を取りに行くので、古い予報を掴んだままにはならない。

### データを集める

```bash
node scripts/resolve-locations.js      # 地点定義を作る（最初に1回）
node scripts/collect-normals.js        # 平年値を取る（最初に1回）

node scripts/collect-forecast.js       # 予報。1日2回
node scripts/collect-observation.js    # 実測。1日1回
node scripts/collect-jma-forecast.js   # 気象庁予報。1日1回
node scripts/build-derived.js          # 画面が読むデータを作り直す
```

GitHub Actions が毎日 01:00 と 06:00 JST に回す。手で叩く必要はない。

### 過去に遡る

```bash
node scripts/backfill-previous-runs.js --from 2024-01-01   # 過去の予報
node scripts/collect-observation.js --from 2023-11          # 過去の実測
node scripts/backfill-archive.js                           # ERA5 1940年〜
```

Open-Meteo の無料枠には時間あたりの上限がある。`HTTP 429` が出た区間は飛ばされる。
取得済みの区間は次回スキップするので、時間をおいて同じコマンドをもう一度叩けば続きから埋まる。

## 地点

| キー | 地点 | 真値の観測所 | 距離 |
|---|---|---|---|
| `setagaya` | 東京都世田谷区 | 東京 | 10.1km |
| `kawasaki` | 神奈川県川崎市 | 横浜 | 11.3km |
| `sagamihara` | 神奈川県相模原市 | 八王子 | 11.8km |
| `atami` | 静岡県熱海市 | 網代 | 5.9km |

観測所は市区町村の代表座標から自動で選んでいる。
最寄りを機械的に取ると雨量しか観測していない観測所に当たるので、
観測要素の数と距離を天秤にかけて選ぶ（距離 10km を要素1つ分と見なす）。

地点を足すには `scripts/resolve-locations.js` の `TARGETS` に1行足して `--force` で走らせる。

## データの出どころ

| 用途 | 出どころ |
|---|---|
| 予報・アンサンブル・過去の予報・ERA5 | Open-Meteo（非商用無料、CC BY 4.0） |
| 実測の日別値・日別平年値・府県天気予報 | 気象庁 |

気象庁の防災情報 JSON は公式 API として提供されたものではない。
仕様変更で取得が止まりうるので、失敗を握りつぶさず収集ログに残し、画面に欠損として出す。

## 作りの要点

- **npm 依存ゼロ。** Node 22 の標準 `fetch` だけ。グラフは SVG と Canvas を自前で描く
- **統計は線形3種。** Ridge 重回帰 / ロジスティック回帰 / 分位点回帰を自前実装。
  勾配ブースティングは使わない。サンプル数に見合わないのと、係数を画面に出せなくなるため
- **前向き検証を崩さない。** ある日を採点するとき、その日より前のデータだけで学習した係数を使う。
  学習範囲は `public/data/leakcheck.json` に出していて、画面の「未来を見ていない証拠」で確認できる
- **生データは追記専用の NDJSON。** 決定論的な id を持たせ、再取得しても行が増えない
- **PWA。** サービスワーカーは、画面の部品をキャッシュ優先・データをネットワーク優先で扱う。
  アイコンの PNG も画像ライブラリを使わず `scripts/lib/png.js` で書き出している
- **天気アイコンは WMO コードから描き分ける。** 形と色だけに頼らず、必ず名前を併記する
- **時間別予報と実況。** 今日と明日は1時間ごとに気温・体感・降水量・降水確率を出す。
  「現在の天気の詳細を取得する」を押すと、気象庁アメダスの10分値を直近6時間ぶんブラウザから直接取る。
  こちらは予報ではなく実際に観測された値なので、予報が今当たっているかをその場で確かめられる

詳しくは `.claude/specs/weather-accuracy/` を見る。
