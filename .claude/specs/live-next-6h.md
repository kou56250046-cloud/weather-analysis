# 実況に「この先6時間の予報」と雨雲の動きへのリンクを足す

## 背景

「現在の天気の詳細」（`public/assets/live.js`）は、アメダスの直近6時間の実測と
モデルの現在値だけを出している。今の天気は分かるが、この後どうなるかは
予報タブの時間別（1日1回のバッチで作るため数時間古い）まで見に行かないと分からない。

押した時点で Open-Meteo から時間別予報を直接取り、直近6時間の実測に続けて
6時間先までを同じ画面に出す。

雨雲レーダーは `weather-accuracy/requirements.md` の非目標のまま据え置き、
気象庁の「雨雲の動き」へ地点の座標付きでリンクするだけにする（2026-09-19 決定）。

## 設計

### 取得

`fetchCurrent` の Open-Meteo 呼び出しに hourly を相乗りさせる。呼び出し回数は増えない。

```
&hourly=temperature_2m,precipitation,precipitation_probability,weather_code,
        wind_speed_10m,wind_direction_10m
&forecast_hours=10
```

- モデルは Open-Meteo の既定（best_match）。予報タブの7モデル平均とは別物で、
  統計補正も当たっていない。そのことを画面に書く
- `forecast_hours` は現在の正時から数える（2026-09-19 12:45 に叩いて 12:00 始まりを確認済み）。
  アメダスの遅れに余裕を持たせて10本取り、起点より後の最初の6本を使う
- **起点**は最新の観測時刻。アメダスが失敗したときは Open-Meteo の `current.time` を使う
- 戻りを `{ current, hourly }` にする。hourly が無い・壊れているときは `hourly: []`
  にして、現在値の表示は続ける（片方が壊れても描く、という既存方針に合わせる）

### 変換（テストできる純関数として切り出す）

- `splitForecast(data)`
  Open-Meteo の応答を `{ current, hourly }` に分ける。`current` が無ければ例外（今と同じ）。
  `hourly` が無い、`time` が配列でない、列の長さが `time` と違うときは `hourly: []`

- `nextHours(hourly, after, count = 6)`
  Open-Meteo の `hourly`（列ごとの配列）を行の配列 `{ at: Date, temp, prcp, pop, code, wind, windDirection }`
  に直し、`at > after` のものを先頭から `count` 本返す。`time` は `timezone=Asia/Tokyo`
  で返る壁時計時刻なので JST として読む。欠けた値は `null` のまま持つ。
  6本に満たなければ取れた分だけ返す（表示側は並べられた分だけ並べ、注記に「N時間分だけ取れた」と書く）
- `degToDir16(deg)`
  Open-Meteo の風向（度、0〜360）をアメダスと同じ 1〜16 の方位番号に直す（北を 16）。
  `windDirName` をそのまま使えるようにする。`null` は `null`
- `radarUrl(loc)`
  `https://www.jma.go.jp/bosai/nowc/#zoom:10/lat:<lat>/lon:<lon>/colordepth:normal/elements:hrpns&slmcs`
  を返す。座標は小数3桁に丸める（`locations.json` は既に市区町村の代表点）。
  2026-09-19 に実際に開き、ハッシュの座標を中心に表示されることを確認した（フォールバックは不要）

### 表示

1. **気温と風のグラフを +6時間まで延ばす**
   - 横軸は10分刻みの枠。過去は観測行、未来は正時の予報点を該当する枠に置く
   - 実測は実線、予報は破線（`line(..., { dash })`）。色は同じ系列色にして、凡例に
     「実測」「予報（補正なし）」を出す
   - 最新の観測時刻に「現在」の縦線と文字を入れる（`tab-forecast.js:246-257` の「いま」線と同じ描き方。
     関数化されていないので同じ形で書く）
   - 実測と予報を線でつながない（別のものなので）
   - 縦軸の範囲は実測と予報の両方の値から決める（破線が枠からはみ出さないように）
   - 十字カーソルの札は、実測の枠なら観測値、未来側の枠ならいちばん近い正時の予報値を出す
   - 見出しは「気温の6時間」から「気温 直近6時間とこの先6時間」に変える
   - （レビュー後に追加）横軸は最初の観測からの10分刻みの番号を**時刻から**振る。アメダスの行が抜けても
     時間が縮まず、抜けた枠で線が切れる。目盛りは正時にだけ置き、予報の終わりの正時にも必ず付ける
   - （レビュー後に追加）予報の風速 0 は「静穏」。降水量は「前1時間」と書く。材料が何も無い時間は推定せず「不明」
2. **降水のグラフは今のまま**（10分値の実測）。1時間値の予報と単位が違うので同じ軸に載せない
3. **「この先6時間」の札の列を新設**。1時間ごとに6枚並べる。既存の `.tiles` / `.tile` を使う
   - 時刻、天気アイコン＋名前（`weatherIcon` / `describeCode`。名前を必ず添える）、
     気温、降水量 mm、降水確率 %、風速と風向
   - `code` が null の札は `inferKind({ prcp, pop })` で推定し、名前に「（推定）」を付ける（`nowPanel` と同じ扱い）
   - 注記:「Open-Meteo の既定モデルの時間別予報。統計補正はしていない。予報タブの値とは少し食い違う」
4. **雨雲の動きへのリンク**を札の列の下に置く。「気象庁 雨雲の動き（この地点付近）」、
   `target="_blank" rel="noopener"`

### 失敗したとき

| 状況 | 表示 |
|---|---|
| アメダスだけ失敗 | グラフは出さない（今と同じ）。札の列とリンクは出す |
| Open-Meteo だけ失敗 | グラフは実測だけ（今と同じ）。札の列の代わりに「この先の予報は取れなかった」 |
| hourly だけ欠ける | 現在値は出す。札の列の代わりに同じ文言 |
| 両方失敗 | 今と同じエラー表示。リンクだけは出す（今の早期 return の前にリンクを足す） |

## 受入条件

- [ ] 実況を開くと「この先6時間」の札が6枚、最新観測時刻より後の正時から1時間刻みで並ぶ
      （アメダスが取れないときは Open-Meteo の現在時刻より後の正時から）
- [ ] 各札に天気のアイコンと名前が両方ある。天気コードが無い札は名前に「（推定）」が付く
- [ ] 予報の札とカーソル表示の風向が16方位の名前で出る（「—」にならない）
- [ ] 気温と風のグラフで、実測が実線、予報が破線で描かれ、両者が線でつながっていない
- [ ] 「現在」の縦線が最新観測時刻の位置にある
- [ ] 補正していない旨が札の列の注記とグラフの凡例に書かれている
- [ ] 雨雲の動きのリンクを押すと、気象庁の雨雲の動きが新しいタブで開く。
      ハッシュで中心を指定できるなら地点付近が中心になる。効かなければハッシュ無しの URL にし、
      その場合はトップが開けばよい（どちらになったかを実装時に仕様へ書き戻す）
- [ ] DevTools で Open-Meteo をブロックしても、実測のグラフと表は今と同じく出て、
      札の列の代わりに「この先の予報は取れなかった」が出る
- [ ] DevTools で jma.go.jp をブロックしても、札の列とリンクは出る
- [ ] 両方ブロックすると、今と同じエラー表示に加えてリンクが出る
- [ ] hourly 欠け・列長不一致は `splitForecast` の単体テストで `hourly: []` になることを確かめる
- [ ] Open-Meteo への通信は押すたびに1回のまま
- [ ] `node --test test/*.test.js` が通る

## 非目標

- 雨雲レーダー画像の自前表示、ナウキャストの取得、地図の描画（非目標のまま据え置き）
- 6時間予報への統計補正。日別最高・最低にしか学習していないため当てる根拠が無い
- 7モデル合議での取得。ブラウザから7モデルを取って平均する処理は持ち込まない
- 降水グラフへの予報の重ね描き（10分値と1時間値で単位が違う）
- 6時間より先、15分刻み（`minutely_15` は日本では1時間値の補間にすぎない）
- 予報の保存・履歴化、予報と実測の答え合わせ
- `sw.js` の変更。外部オリジンは素通しなのでキャッシュ方針は変わらない。
  部品は裏で取り直す方針なので `CACHE_VERSION` も上げない
- 予報タブ（`tab-forecast.js`）の時間別表示の変更

## 触るファイル

- `public/assets/live.js` — hourly の相乗り取得、`nextHours` / `radarUrl` の追加、
  気温・風グラフの延長、札の列とリンクの追加、失敗時の分岐
- `test/live.test.js` — `splitForecast`（hourly 欠け・列長不一致で空）、`nextHours`（JST として読む・
  `after` より後だけ・6本で切る・足りなければ取れた分・欠けた値が null）、`degToDir16`（0/360 が北、
  90 が東、null）、`radarUrl`（座標の丸め、形式）のテスト

## 検証方法

1. `node --test test/*.test.js`
2. `node scripts/serve.js` で配信し、claude-in-chrome で実況を開いて受入条件を目視で確かめる
3. リンクの URL の書式（`#zoom:.../lat:.../lon:...`）が実際に地点付近を中心に開くか確かめる。
   中心が効かなければハッシュ無しの `https://www.jma.go.jp/bosai/nowc/` に落とす
4. DevTools のネットワークブロックで失敗時の表のうち3行（アメダス失敗・Open-Meteo 失敗・両方失敗）を確かめる。
   hourly 欠けは単体テストで確かめる
