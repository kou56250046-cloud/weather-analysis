# 過去予報に湿度と風を補い、日別の湿度・風速にも統計補正を効かせる — 要件

## 背景

日別の最高・最低気温と降水は統計補正（MOS）で誤差が 30〜40% 縮み、気象庁予報より良い。
一方、湿度と風速は補正が一度も動いていない。4地点とも検証できた日数が 4〜6 日しかないため
（学習には 70 サンプル要る。`scripts/lib/calibrate.js:13,264`）。

原因は過去予報の遡り取得（`backfill-previous-runs.js`）が API 使用量を抑えるため気温と降水しか取っておらず、
2024-01〜2026-09-11 の 39,179 行すべてで `rh` と `wind` が null であること。実測の湿度・風は 2023-11 から揃っている。

湿度と風を遡って取り直せば、約 990 日 × lead 1〜7 のサンプルができ、補正がすぐ動く（2026-09-19 ユーザー依頼）。

## 受入条件

- [ ] `public/data/scores-<loc>.json` の 4 地点すべてに、`variable` が `rh` と `wind` で `source` が `blend:mos` の行が lead 1〜7 それぞれにあり、`n` が 700 以上
- [ ] **湿度（合否）**: 4地点 × lead 1〜7 の 28 組すべてで、`blend:mos` の MAE が同じ組の `baseline:mean` の MAE より小さい
- [ ] **風速（参考＋合否1つ）**: 予報は日最大・実測は日平均で定義が違い、`baseline:mean` との比較は補正の効き目を示さないので参考として報告する。
      合否は「28 組すべてで `blend:mos` の bias の絶対値が 0.3 m/s 以下」（定義の差による偏りを補正が消せていること）
- [ ] `public/data/leakcheck.json` に rh と wind が lead 1〜7 それぞれで載り、`evaluatedFrom` と `lastTrainTo` が null でなく、
      `evaluatedFrom` が補完データの最初の対象日から 60 日以上後になっている。前向き検証そのものは `walkForwardRidgeMulti` の既存テストが担保する
- [ ] 最高・最低気温と降水の成績（`blend:mos` の tmax / tmin / rain / pop 行）が、補完の有無で変わらない。
      比べ方: 同じチェックアウトで `data/fcst-supp` を一時退避して build-derived → 戻して build-derived、の2つの `scores-*.json` を突き合わせ、該当行が完全一致
- [ ] `data/fcst-supp/**` と再計算した `public/data/*.json` をコミットし、main に反映する。反映しないと、次の定期実行（collect.yml が build-derived を回し直す）で補正が消える
- [ ] 既存の `data/fcst/**` のファイルは1バイトも変わらない（`git diff --stat data/fcst` が空）
- [ ] 取り直しの処理を2回続けて実行しても、補完データの行数が増えない（冪等）
- [ ] 途中で止めて再実行すると、取得済みの区間は API を叩かずに飛ばす
- [ ] 1回の実行の call 見積もりを実行前に表示し、8,000 を超えるなら中止する。見積もりは Open-Meteo の重み（変数数/10 × 日数/14 の小数）で計算する
- [ ] `node --test test/*.test.js` が通る

## 非目標

- 既存の予報行（`data/fcst/**`）の書き換え・置き換え。追記専用の規約を守る
- 予報の風速の定義変更（今は日最大。実測は日平均）。定義の差は MOS が吸収する。毎日の収集とも揃ったまま
- 日照（sun）の取り直し。MOS の対象外なので API 使用量を増やすだけ
- lead 0 と lead 8〜16 の補完。previous-runs で取れないので、毎日の収集が貯まるのを待つ
- 予報タブに日別の湿度・風速を表示すること（今は時間別だけ）。補正の成果は成績タブに出る。表示は別タスク
- 成績タブの係数表・未来を見ていない証拠の表を rh/wind に広げること（今は最高気温で固定）
- GitHub Actions の backfill ワークフローの変更。取り直しは一度きりなのでローカルで手動実行する
- 時間別・「この先6時間」の補正

## 制約

- npm 依存ゼロ。Node 標準だけ
- Open-Meteo 非商用枠: 10,000 call/日、5,000/時、600/分。毎日の収集が約 110 call/日を使う
- NDJSON は追記専用。行の `id` は決定的。スキーマを変えたら `v` を上げ旧版も読めるようにする
- 画面に出す精度は前向き検証の値だけ（学習データでの当てはまりを出さない）
- 時刻の変換は `lib/time.js` の関数だけを使う
