# design — 解説タブ

## 置き場所

`public/assets/tab-method.js` を新設し、`renderMethod({ data, loc, meta })` を公開する。
既存4タブと同じ契約（`el()` の配列を返す）。

```js
// app.js
import { renderMethod } from './tab-method.js';
const TABS = [ … , { id: 'method', label: '解説', render: renderMethod } ];
const names = { … , method: [`scores-${loc}.json`, `coef-${loc}.json`] }[tab];
```

冒頭コメントの「タブ4枚と地点切り替え」も5枚に直す。

`loadFor` は `Promise.allSettled` なので、読めなければ `null` が入る。
解説本文は data を参照せずに組み、実値の差し込みだけを `data?.scores` / `data?.coef` に依存させる。

## 数式をどう組むか

CDN 不使用の制約があるので MathJax / KaTeX は使えない。
この画面に出る式は「分数・平方根・総和・上下付き・ギリシャ文字」で足りる。
汎用の組版は作らず、次の5部品だけ用意する。

| 部品 | 役割 | 出力 |
|---|---|---|
| `fx(...parts)` | 式ブロック1本 | `div.formula`（横スクロール可） |
| `frac(num, den)` | 分数 | `span.frac` に上段・下段 |
| `sqrt(...inner)` | 平方根 | `span.sqrt`（記号 + 上線） |
| `sum(under, over)` | 総和記号 | `span.bigop` に Σ と上下の添字 |
| `sym(name, desc)` | 記号の説明 | `dl.symbols` の1組 |

上下付きは素の `<sub>` `<sup>`、ギリシャ文字と演算子は Unicode
（Σ β λ τ σ ρ Ω ∇ ≥ ≤ − × ⁻¹ ² √ ∈ ∂ ᵀ）をそのまま使う。
数式に画像を使わない。読み上げと選択コピーができなくなるため。

`body` は `font-feature-settings: "tnum" 1`（`style.css:117`）で等幅数字になっているが、
式ブロックにはセリフ寄りの書体を別に当てて本文と見分けられるようにする。

### CSS（style.css に追記）

```
.formula        背景 var(--plane) / 左罫 3px var(--series-1) / overflow-x:auto / セリフ体
.formula .frac  inline-flex column、上段に border-bottom
.formula .sqrt  √ + span.radicand に border-top
.formula .bigop Σ を 1.4em、上下の添字を 0.62em で縦積み
.symbols        grid（記号 / 説明）の2列。560px 未満では1列に落とす
.method-toc     章へ飛ぶボタンの並び
```

新しい色変数を増やさない。既存の変数だけで組む。

## 章構成と載せる式

### 1. 数値予報の仕組みと限界

- 大気を格子に切り、支配方程式を初期値から時間積分する、という骨格
  - 運動方程式 `Du/Dt = −(1/ρ)∇p − 2Ω×u + g + F`
  - 連続の式 `∂ρ/∂t + ∇·(ρu) = 0`
  - 熱力学 `c_p DT/Dt − (1/ρ) Dp/Dt = Q`
  - 状態方程式 `p = ρRT`
  - 水蒸気の保存 `Dq/Dt = S`
  - 意味は1行ずつ。解き方には踏み込まない（非目標）
- 初期値鋭敏性 `δ(t) ≈ δ₀ exp(t/τ)`。τ は数日の程度で、これが予測可能性の限界を決める
- アンサンブル予報。初期値と物理過程を少し変えた M 本を走らせ、分布として読む
- 複数モデルの合議が効く理由（誤差の相関 ρ̄ が小さいほど効く）

  `Var(平均) = σ² (1 + (K−1)ρ̄) / K`

- 格子は地形を平滑化する。代表点の標高と観測所の標高がずれるため、モデル出力には
  地点固有の系統誤差が残る。これが統計補正の出番。熱海を対象地点に入れている理由

### 2. 降水確率

- 気象庁の定義。予報対象の時間内に **1mm 以上** の降水がある確率。10% 刻み。
  量でも、降る時間の割合でも、降る面積の割合でもない
- アンサンブルからの素の確率（`openmeteo.js:240`）

  `P_raw = (1/M) Σ_{m=1..M} 1[ R_m ≥ 1.0 mm ]`

  M は ECMWF / GFS のアンサンブルメンバー数
- 素の比率は較正されていない。ロジスティック回帰で実測に合わせ直す（`blend.js:62`）

  `P = σ(βᵀx) = 1 / (1 + exp(−βᵀx))`

- 較正が効いているかは、較正後の `P` をそのまま採点して確かめる。
  `build-derived.js` の `buildMosForecastRows` に `rain` の前向き検証予測を `pop` として通し、
  `blend:mos / pop` の Brier score・BSS・信頼度図を出す（T0 で実装）。
  採点に使う `P` は前向き検証の予測なので、その日の実測は係数の学習に入っていない

### 3. 予報を採点する指標

連続値（気温・湿度・風速）— `verify.js:23`

- `MAE = (1/n) Σ |f_i − o_i|`
- `RMSE = √( (1/n) Σ (f_i − o_i)² )`、`RMSE ≥ MAE`。大外しに敏感
- `bias = (1/n) Σ (f_i − o_i)`。符号付き。系統的な高め・低めを見る
- ここに C6-1 の実値を差し込む

降水の有無（2×2 分割表）— `verify.js:58`

|  | 実測あり | 実測なし |
|---|---|---|
| 予報あり | H | F |
| 予報なし | M | C |

- `適中率 = (H + C) / N`
- `空振り率 = F / (H + F)`
- `見逃し率 = M / (H + M)`
- `捕捉率（雨の日を当てた率）= H / (H + M)`
- 偶然の当たりを差し引いた ETS

  `H_rand = (H + F)(H + M) / N`
  `ETS = (H − H_rand) / (H + F + M − H_rand)`

- 適中率だけ見ると「毎日降らないと言う」が高得点になる罠を明示
- ここに C6-2 の実値を差し込む

確率 — `verify.js:98`

- `BS = (1/n) Σ (p_i − o_i)²`、`o_i ∈ {0, 1}`
- `BS_clim` は常に気候値 `ō` を言う予報の Brier score
- `BSS = 1 − BS / BS_clim`。0 以下なら気候値を言うのと変わらない
- 信頼度図。ビン k に入った日の実測頻度が、そのビンの平均予報確率に一致すれば較正済み
- ここに C6-4 の実値（`blend:mos / pop` の BS・BS_clim・BSS）を差し込む

区間 — `verify.js:160`

- `被覆率 = (1/n) Σ 1[ l_i ≤ o_i ≤ u_i ]`。80% 区間なら 0.8 に近いのが正直
- **注記**: 画面の被覆率は、分位点回帰が学習できた lead についてのみ、
  `clampAround` で中央値の周りに付け直す**前**の上下端で測っている
  （`build-derived.js:322-334`）。3段フォールバックの区間の被覆率ではない
- ここに C6-3 の実値を差し込む

スキルスコアの一般形 `SS = 1 − S / S_ref` を1行置く。

### 4. このシステムの算出方法

データ源（一括りにしない）

| 役割 | 出どころ |
|---|---|
| 予報（合議のタネ） | Open-Meteo 経由の7モデル |
| 分位数・素の降水確率 | Open-Meteo のアンサンブル（ECMWF / GFS） |
| **検証の真値** | 気象庁「過去の気象データ」の日別値（`src:'etrn'`、`collect-observation.js:42`） |
| 実況表示 | 気象庁アメダスの10分値（ブラウザから直接。`live.js`） |
| 比較対象 | 気象庁の府県天気予報 |
| 長期 | ERA5 再解析 |
| 平年値 | 気象庁公表の 1991–2020 日別平年値 |

説明変数（`calibrate.js:51-88`）

- 気温・湿度・風速

  `x = [ 1, f₁, …, f₇, sin(2πd/365.2425), cos(2πd/365.2425) ]ᵀ`

- 降水（量・有無の両方）— 説明変数にも `log1p` がかかる

  `x = [ 1, log(1+f₁), …, log(1+f₇), sin, cos ]ᵀ`

- `d` は通日。欠けたモデルはその行の他モデルの平均で埋め、列は固定する（理由も書く）

MOS（連続値）— `regress.js:23`

  `ŷ = β₀ + Σ_{m=1..7} β_m f_m + β_s sin + β_c cos`

  `β̂ = argmin { Σ (y_i − βᵀx_i)² + λ Σ_{j≥1} β_j² }`
  `β̂ = (ZᵀZ + λW)⁻¹ Zᵀy`, `W = diag(0, 1, …, 1)`

  標準化してから解いて元のスケールへ戻す理由（気温 20 前後と季節項 −1〜1 に同じ λ を
  かけると、正則化の強さが列ごとにばらばらになる）。
  λ は {0.01, 0.1, 1, 10, 100} を全部試し、前向き検証の MAE が最小のものを選ぶ。
  選ばれた λ と学習日数は `coef-<loc>.json` から差し込む

- 降水量は `log(1+R)` で回帰し `exp(ŷ)−1` で戻す（裾が右に長いため）
- 降水の有無はロジスティック回帰（IRLS、`regress.js:62`）。完全分離を避けるため常に弱い L2
- 予測区間は3段構え（`blend.js:94`）
  1. 分位点回帰 τ = 0.1, 0.9。損失は `ρ_τ(r) = r(τ − 1[r<0])`
  2. 無ければアンサンブルの p10/p50/p90 の幅を借りる
  3. それも無ければ `± 1.28 × MAE`（正規分布の 80% 区間、z₀.₉ ≈ 1.2816）
  どの経路でも区間は必ず表示する予報値を含むように付け直す
- 前向き検証（リーク禁止、`calibrate.js:101`）

  `ŷ_i = β̂(D_{<i})ᵀ x_i`,  `D_{<i} = { (x_j, y_j) : j < i }`

  - 総サンプルが 70 本（`MIN_TRAIN + 10`）に満たない区分は、そもそも学習しない
  - 予測を出し始めるのは 60 本目（`MIN_TRAIN`）から
  - 学習し直しは Ridge が7日ごと、反復解法（ロジスティック・分位点）が28日ごと。
    その間は直近の係数を使い回す
- 天気コードの合議（`build-derived.js:169`）。荒天の度合いで並べて中央を採る。
  平均は意味を持たない（コード番号は順序尺度ですらない箇所がある）
- 平年差 `a = o − N(mm-dd)`。平年値は気象庁の公表値をそのまま使い、平滑化しない
- ERA5 と実測の系統差 `offset = median(ERA5 − 実測)`（重複が30日未満なら測らない）。
  線をつながずオフセットを明示する
- 移動平均（`tab-analysis.js:124`）

  `s_t = (1/|W_t|) Σ_{k∈W_t} y_k`,  `W_t = [t−5, t+5]`（11点）

  有効な点が窓幅の半分に満たない端は描かない
- 欠測の扱い。系統が2つあるので分けて書く
  - 検証に使う日別値 … 品質フラグが 1 以下の値だけ使う（`verify.js:9,19`）
  - 実況のアメダス10分値 … フラグが 0 のものだけ使う（`live.js:27`）。
    ただし **値としての 0 は欠測ではない**
  - 欠測は 0 で埋めない。グラフで線をつながない
- 時間別予報には補正が当たっていないこと（日別の最高・最低に対して学習しているため）

### 5. この方法の限界

- 学習しているのは日別の `tmax` `tmin` `rh` `wind` `prcp` だけ。時間別は7モデルの単純平均
- サンプルが 70 本貯まるまで MOS は働かず、補正なしの単純平均が出る
- 較正後の降水確率の検証は、実測が貯まった lead でしか出せない。
  降水日が少ない期間では `BS_clim` が小さくなり BSS が不安定になる
- 予報側の日別値は時間別を 00〜23 時で畳んだもの（24点中18点以上を要求）。
  気象庁の日界 00:10〜24:00 とはずれる。この系統差は MOS が吸収する前提
- 日別実測に「日内の観測個数」は持っていない。足切りは品質フラグだけ
- ERA5 は格子点の推定値。観測所の実測とは別物
- 気象庁 bosai JSON は公式 API ではない
- 地点は `config/locations.json` の4つだけ

## 実データの差し込み

`data.scores.rows` / `data.scores.coverage` / `data.coef` から引く。
引けなければその行ごと省く（本文は残る。C7）。

| 置く場所 | 引く行 | 備考 |
|---|---|---|
| MAE / RMSE / bias | `source='blend:mos', variable='tmax', lead=3` | 無ければ最小 lead |
| 分割表と ETS | `source='blend:mos', variable='rain'` の最小 lead | |
| 被覆率 | `scores.coverage['tmax|3']` | 付け直し前の区間である旨を併記 |
| Brier / BSS | `source='blend:mos', variable='pop'` の最小 lead | T0 で生成する行 |
| λ と学習日数 | `coef.coefficients` の `variable='tmax'` | |

T0 で `blend:mos / pop` の行を出すようにしたうえで差し込む。
無い地点（降水日が少なく `BS_clim = 0` になる等で `brierSkillScore` が `null`）では
その行だけ省き、式の説明は残す。
