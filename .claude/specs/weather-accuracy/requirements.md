# requirements — 予報精度検証システム + 気象データ分析ダッシュボード

## 背景

Apple 天気や Yahoo 天気の予報、特に一週間先がほぼ外れるという実感がある。
実感を数字で裏付け、それより当たる予報を自分で作り、あわせて過去の気象データを分析したい。
完全個人・無料運用。

既存アプリの弱点は予報そのものの質ではなく、見せ方と検証の欠如にある。

- 単一ソースの決定値しか出さない。Yahoo は気象庁発表、Apple は The Weather Channel が元
- 地点固有の系統誤差を補正しない
- 外れた実績を一切開示しない。7日先の予報も明日の予報も同じ顔で表示される

ここに3つの勝ち筋がある。合議、統計補正（MOS）、精度の開示。
最も価値が大きいのは3番目。どこまで信じてよいかが分かる予報にする。

## 受入条件

### 収集

- [ ] A1. 7モデル（ECMWF / GFS / ICON / JMA / UKMO / GEM / Météo-France）の予報を4地点分、1日2回取得して NDJSON に追記できる
- [ ] A2. 同じスクリプトを連続2回実行しても NDJSON の行数が増えない（決定論的 id による冪等性）
- [ ] A3. 気象庁アメダスの10分値から前日の日次代表値（最高/最低気温・降水量・平均湿度・最大風速・日照時間）を作り、観測個数 `n` とともに保存できる
- [ ] A4. 気象庁府県天気予報を同じ形式で保存し、自作予報と同じ関数で採点できる
- [ ] A5. Previous Runs API で過去の予報を lead 1〜7 について遡って一括取得できる
- [ ] A6. Archive API で ERA5 の日次データを 1940 年以降について一括取得できる
- [ ] A7. いずれかのソースが落ちても他の収集が完走し、失敗は `data/collect-log.ndjson` に記録される

### 計算

- [ ] B1. `(loc, target, model, lead)` で予報と実測を突き合わせ、MAE / RMSE / 平均バイアス / 降水の分割表 / Brier score を算出できる
- [ ] B2. 重回帰（Ridge）・ロジスティック回帰・分位点回帰を依存ゼロで実装し、合成データで係数を復元できる
- [ ] B3. MOS の係数を前向き検証で学習し、評価日より後のデータを一切使っていないことをログで確認できる
- [ ] B4. 前向き検証の MAE が「単純平均」「最良の単独モデル」のいずれよりも小さい
- [ ] B5. 80% 予測区間の被覆率が 70〜88% に収まる
- [ ] B6. 降水確率の reliability diagram が概ね対角線に乗る
- [ ] B7. ERA5 1991-2020 から日別平年値を作り、アメダス実測との系統差をオフセット補正できる

### 画面

- [ ] C1. 4タブ（予報 / 成績 / 平年比 / 分析）を地点切り替え付きで表示する
- [ ] C2. 予報タブで補正済み合議予報を 1〜16 日分、予測区間の帯とともに表示し、日ごとに実績誤差を添える
- [ ] C3. 成績タブでモデル × lead の誤差ヒートマップ、誤差の推移、降水の的中率、モデルランキング、学習された係数を表示する
- [ ] C4. 平年比タブで今月・今年の気温と降水を平年値と比較表示する
- [ ] C5. 分析タブで年次トレンドと、条件を指定した過去日の抽出・月別頻度集計ができる
- [ ] C6. 欠測日がグラフ上で線で繋がれない
- [ ] C7. スマートフォン幅（400px）で横スクロールが発生しない
- [ ] C8. Open-Meteo の CC BY 4.0 出典表示がフッターにある

### 運用

- [ ] D1. GitHub Actions の cron で毎日自動収集され、差分があるときだけコミットされる
- [ ] D2. `public/**` の変更時のみ Pages が再配信される
- [ ] D3. 最終収集成功時刻が画面に表示され、収集が止まったら気づける
- [ ] D4. npm 依存ゼロ。`npm install` なしで全コマンドが通る

## 非目標

- 雨雲レーダー・ナウキャストなど分単位のリアルタイム表示
- 自前の数値予報モデルの実行。既存モデルの出力を合議・補正するところまで
- 全国地図表示。対象は定義した4地点のみ
- 通知・アラート機能。第2期以降の候補
- 商用利用・第三者への提供。Open-Meteo の非商用枠と CC BY の範囲に留める
- Apple / Yahoo のアプリから直接スクレイピングして比較すること。
  規約上の問題があるため、比較対象は公開されている気象庁予報を代理指標とする
- 非線形の機械学習。勾配ブースティングやニューラルネットは第1期では使わない。
  統計補正は重回帰・ロジスティック回帰・分位点回帰の線形3種を自前実装する範囲に留め、
  Python や scikit-learn への依存を持ち込まない
- `file://` での直接オープン対応。ローカルでも簡易サーバー経由で見る
- ユーザー登録・認証・複数ユーザー対応

## 検証方法

| 対象 | 方法 |
|---|---|
| 地点解決 | 解決されたアメダス観測所名と距離を出力し、常識的な近さか目視確認する |
| 収集 | `--dry-run` で生成レコードを出す。2回連続実行して行数が増えないことを確認 |
| 日次集計 | 既知の1日分を渡し、気象庁公式ページの日別値と一致することを確認 |
| 誤差計算 | 手計算できる小さな配列で MAE / RMSE / Brier score が期待値と一致することを確認 |
| 回帰 | 既知の係数で作った合成データから係数を復元。分位点回帰は一様分布で p10 / p90 が理論値と一致 |
| MOS の効果 | 前向き検証で 単純平均 / 最良単独モデル / MOS を同期間で比較し MOS が最小になることを確認 |
| リーク防止 | 係数の再計算日と使用データの日付範囲をログに出して確認 |
| 予測区間 | 80%区間の被覆率を計算して 70〜88% を確認 |
| 画面 | `node scripts/serve.js` で配信し claude-in-chrome で開く。Playwright は `file://` を開けないため使わない |
| Actions | `workflow_dispatch` で手動実行し、コミットと Pages 更新を確認してから cron を有効にする |
