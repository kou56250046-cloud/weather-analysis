# design — 予報精度検証システム + 気象データ分析ダッシュボード

## データソース

すべて無料・API キー不要。

| 用途 | エンドポイント | 備考 |
|---|---|---|
| 予報 | `https://api.open-meteo.com/v1/forecast` | 非商用無料。10,000 call/日、5,000/時、600/分 |
| アンサンブル | `https://ensemble-api.open-meteo.com/v1/ensemble` | ECMWF 51 / GFS 31 / ICON 40 メンバー |
| 過去の予報 | `https://previous-runs-api.open-meteo.com/v1/forecast` | `*_previous_day1`〜`_day7`、`past_days` 最大7 |
| 長期アーカイブ | `https://archive-api.open-meteo.com/v1/archive` | ERA5、1940〜。5日遅れ |
| 実測（日別値） | `https://www.data.jma.go.jp/obd/stats/etrn/view/daily_a1.php` / `daily_s1.php` | 気象庁の公式日別値。`prec_no` + `block_no` + `year` + `month` の GET。1リクエストで1か月分 |
| 都府県コード表 | `https://www.data.jma.go.jp/obd/stats/etrn/select/prefecture00.php` | 都府県名 → `prec_no` |
| 観測所表 | `https://www.data.jma.go.jp/obd/stats/etrn/select/prefecture.php?prec_no=NN` | `block_no`・緯度経度・要素の有無。地点解決に使う |
| 比較用予報 | `https://www.jma.go.jp/bosai/forecast/data/forecast/{areaCode}.json` | Yahoo 天気の元データ |
| 日別平年値 | `https://www.data.jma.go.jp/stats/etrn/view/nml_amd_d.php` / `nml_sfc_d.php` | 1991-2020 の公表値。1リクエストで1か月分 |
| 予報区コード表 | `https://www.jma.go.jp/bosai/common/const/area.json` | 地域コード解決に使う |

**ライセンス** Open-Meteo は CC BY 4.0。フッターに出典を明記する。
気象庁 bosai 系 JSON は公式 API ではないため仕様変更リスクがある。失敗をログに残し、画面に欠損として出す。

**モデル** `ecmwf_ifs025` / `gfs_seamless` / `icon_seamless` / `jma_seamless` /
`ukmo_seamless` / `gem_seamless` / `meteofrance_seamless`。
予報可能日数はモデルごとに違う（Météo-France 4日 〜 GFS 16日）。

Previous Runs API は `*_previous_dayN` の**日別変数に対応していない**（400 が返る）。
時間別で取得し、JST の暦日に自前で畳む。1時間値の24点から日最高・最低を作るので、
気象庁の日別値（00:10〜24:00 の連続観測）とは系統的にわずかにずれる。このずれは MOS が吸収する。

**API の課金単位** 変数を増やすほど、期間を長く取るほど1リクエストの重みが増える。
- Previous Runs のバックフィルは既定で気温と降水だけ（`--vars all` で5変数）
- ERA5 アーカイブは最高気温・最低気温・降水量の3つだけ
それでも 1940 年からの86年分を4地点取ると時間あたりの上限に当たる。
取得済みの区間を飛ばす作りにしてあるので、429 が出たら時間をおいて再実行すれば続きから埋まる。

## 時刻の扱い

- `run` は UTC。ISO 8601 で `Z` 付き
- `target` / `date` は JST の暦日。`YYYY-MM-DD`
- Open-Meteo へのリクエストは `timezone=Asia/Tokyo` を付け、返る時刻を JST として扱う
- 変換は `lib/time.js` の関数のみを使う。素の `new Date()` で暦日を作らない

## データモデル

追記専用 NDJSON。全行に `v`（スキーマ版）と `id`（決定論的キー）を持つ。

### 予報 `data/fcst/<loc>/<YYYY-MM>.ndjson`

```json
{"v":1,"id":"setagaya|ecmwf_ifs025|2026-09-12T01:00Z|2026-09-15",
 "loc":"setagaya","model":"ecmwf_ifs025","fetched":"2026-09-12T01:00Z",
 "target":"2026-09-15","lead":3,
 "tavg":23.5,"tmax":28.4,"tmin":19.1,"prcp":2.3,"pop":0.35,"wind":4.2,"rh":68,"code":61,
 "q":{"tmax":[24.1,26.8,28.4,30.0,32.2],"prcp":[0,0,1.2,4.0,9.5]}}
```

**`fetched` はモデルの初期時刻ではなく、こちらが取得した時刻を時単位に丸めたもの。**
Open-Meteo は初期時刻を返さないので、「いつ見た予報か」を基準に lead を数える。
`lead` = `target` − `fetched` の JST 暦日差。`q` は分位数 p10/p25/p50/p75/p90。
アンサンブルは `ecmwf_ifs025` と `gfs_seamless` の2つだけ取得し、`model` が一致する行に付ける。
`pop` はアンサンブルの降水メンバー比率。アンサンブルの無いモデルでは `null`。

### 気象庁予報 `data/jma-fcst/<loc>/<YYYY-MM>.ndjson`

同じ形。`model` は `"jma_official"`、`run` は発表時刻、`q` は持たない。

### 実測 `data/obs/<loc>/<YYYY>.ndjson`

```json
{"v":1,"id":"setagaya|2026-09-12","loc":"setagaya","date":"2026-09-12",
 "tavg":25.4,"tmax":29.1,"tmin":20.3,"prcp":0.0,"prcpMax1h":0.0,
 "rh":71,"rhMin":50,"wind":1.5,"windMax":3.8,"gust":7.4,"sun":8.2,"snow":null,
 "q":{"tmax":0,"prcp":0},"src":"etrn"}
```

**真値は気象庁の公式日別値を使う。** 自前で10分値を集計すると公式値とずれる余地が残るうえ、
`bosai` のアメダス JSON は直近10日ほどしか遡れず、過去の予報を検証できない。
`etrn` の日別値なら数十年遡れるので、Previous Runs API で取った過去の予報を初日から検証できる。

`q` は品質マーク由来のフラグ。ページ上の記号を次の通り読み替える。

| 記号 | 意味 | `q` | 扱い |
|---|---|---|---|
| （なし） | 正常値 | 0 | 使う |
| `)` | 準正常値。1個以上の欠測を含むが値は使える | 1 | 使う |
| `]` | 資料不足値 | 2 | 検証から除外 |
| `--` | 現象なし | 0 | 0 として扱う |
| `///` `×` 空欄 | 欠測・観測実施せず | 3 | `null` |

`q` が 2 以上の項目はその変数だけ検証から除外する。日ごと丸ごとは落とさない。
欠測項目は `null`。0 で埋めない。

### ERA5 アーカイブ `data/archive/<loc>/era5-daily.ndjson`

```json
{"v":1,"id":"setagaya|1991-05-04","loc":"setagaya","date":"1991-05-04",
 "tmax":22.1,"tmin":11.8,"prcp":0.0,"wind":3.1,"rh":64,"sun":9.1}
```

### 収集ログ `data/collect-log.ndjson`

```json
{"v":1,"ts":"2026-09-13T01:00:12+09:00","job":"forecast","ok":true,
 "added":112,"errors":[],"durationMs":8421}
```

### 保存量

日次代表値のみ恒久保存。7モデル × 16 lead × 4地点 × 2回/日 ≒ 900行/日 ≒ 年 25〜35MB。
時間別は直近72時間だけ `public/data/hourly.json` に持ち、履歴に残さない。
前年以前のファイルは `gzip` 化する（読み込み側は `.ndjson` と `.ndjson.gz` の両方を見る）。

## 派生計算

`build-derived.js` が収集後に全体を総再計算する。増分更新にしない。
ロジックを直したとき過去へ遡って効くことを優先する。

### 1. 検証 `lib/verify.js`

`(loc, target, model, lead)` で予報と実測を突き合わせる。

- 連続値（tmax / tmin / wind / rh）: MAE、RMSE、平均バイアス、サンプル数
- 降水有無（`prcp >= 1.0mm` を「降った」とする）: 分割表（hit / false alarm / miss / correct negative）、
  適中率、空振り率、見逃し率、しきい値 0.5 での Brier score
- 降水確率: Brier score と reliability diagram 用のビン集計（10分割）

気象庁予報も同じ関数で採点する。

### 2. MOS（重回帰 + Ridge） `lib/regress.js` / `lib/calibrate.js`

`(loc, 変数, lead)` ごとに学習する。

説明変数 x:
```
[1, f_ecmwf, f_gfs, f_icon, f_jma, f_ukmo, f_gem, f_meteofrance,
 sin(2π·doy/365), cos(2π·doy/365)]
```
目的変数 y: 実測値。欠けたモデルは、そのモデル列を落とした部分集合で別々に学習するのではなく、
**その行の当該列に全モデル平均を入れて埋める**（列の欠落で設計行列が変わるのを避ける）。
埋めたことを示すフラグ列は持たない（サンプル数に対して変数が増えすぎるため）。

解法: 正規方程式 `(XᵀX + λI)β = Xᵀy` を Cholesky 分解で解く。
切片には正則化をかけない（λ を対角の先頭要素だけ 0 にする）。
説明変数は平均0・分散1に標準化してから解き、係数を元のスケールへ戻す。

λ の選択: 候補 `[0.01, 0.1, 1, 10, 100]` を前向き検証の MAE で比較して選ぶ。

縮小推定: `(loc, 変数, lead)` のサンプル数が `MIN_SAMPLES`（既定 120）未満のとき、
lead をまとめた回帰の係数 β_pool との加重平均 `w·β + (1−w)·β_pool`、`w = n / (n + MIN_SAMPLES)` を使う。

### 3. 降水確率の較正（ロジスティック回帰）

説明変数: 各モデルの `prcp`（`log1p` 変換）、アンサンブルの降水メンバー比率、季節項。
目的変数: `prcp >= 1.0mm` の 0/1。IRLS で解く。反復は最大50回、
係数の変化が 1e-8 を下回ったら収束とみなす。完全分離時の発散を防ぐため L2 を常に少量かける。

### 4. 予測区間（分位点回帰）

同じ説明変数で τ = 0.1 と 0.9 を直接推定する。損失はピンボール損失。
最適化は劣勾配降下（学習率 0.01、反復 2000、モーメンタム 0.9）。初期値は重回帰の解。
被覆率で妥当性を測る。

### 5. 平年値 `lib/normals.js`

**1991-2020 の気象庁実測日別値から直接作る。** `etrn` で遡れるので ERA5 を経由しない。
±5日窓の移動平均で平滑化し、うるう日は 2/28 に寄せる。
観測所の移転や欠測で期間が埋まらない場合は、その日の有効サンプル数を持たせて画面に出す。

ERA5（`archive`）は 1940 年からの長期トレンド表示にのみ使う。
実測と系統差があるので、重ねて表示するときは両者の重複期間の差の中央値でオフセットを合わせる。

### 6. 前向き検証

評価対象日 `d` の予報を評価するとき、学習に使ってよいのは `target < d` の行のみ。
`build-derived.js` は総再計算なので、日ごとに係数を再学習する。
計算量を抑えるため、**係数の再学習は7日ごと**にし、その間は直近の係数を使い回す。
再学習日と学習データの日付範囲を `public/data/leakcheck.json` に出力する。

## 画面

タブ4枚。地点切り替えは全タブ共通のヘッダ。

1. **予報** 合議予報 1〜16日。予測区間の帯、モデル間のばらつき、気象庁予報の重ね描き。
   日ごとに「lead 3日の実績誤差 1.2℃」を添える。直近72時間の時間別グラフ。
2. **成績** モデル × lead の誤差ヒートマップ、誤差の時系列、降水の適中率、
   reliability diagram、ランキング（自作合議 / 各単独モデル / 気象庁）、学習係数の表示。
3. **平年比** 今月・今年の気温と降水 vs 平年値。偏差の帯グラフ、月別積み上げ。
4. **分析** 1940年からの年次トレンド、猛暑日・真夏日・熱帯夜・降水日数の推移、
   条件クエリ（気温・湿度・降水・風速の上下限 + 連続日数）による過去日抽出と月別頻度。

## リスクと対策

| リスク | 対策 |
|---|---|
| 気象庁 bosai JSON の仕様変更 | 失敗を例外にせずログに記録。予報側は動き続ける。画面に欠損として表示 |
| cron が60日の無活動で停止 | 毎日コミットするため活動は継続。最終成功時刻を画面に出して気づけるようにする |
| Open-Meteo のレート超過 | 通常運用は上限の1%未満。バックフィル時のみ 1.2秒間隔の制御を入れる |
| リポジトリ肥大化 | 日次代表値のみ恒久保存。前年以前は gzip |
| 実測の欠測 | 品質フラグ `q` を持たせ、資料不足・欠測の項目を変数単位で検証から除外 |
| 自宅位置の公開 | 市区町村代表点と最寄りアメダス観測所に丸める |

## 実装して分かったこと

仕様を書いた時点では見えていなかったこと。次に触るときの前提になる。

### 気象庁の週間予報は、こちらの観測所を予報していないことがある

府県天気予報の気温は、府県ごとの代表地点（神奈川なら横浜、静岡なら静岡）についてしか出ない。
気象庁が予報している地点と、こちらが真値に使う観測所が一致するかを `tempMatch` に持たせてある。

| 地点 | 真値の観測所 | 気象庁の週間予報の気温地点 | 気温を比較できるか |
|---|---|---|---|
| 世田谷 | 東京 (44132) | 東京 (44132) | できる |
| 川崎 | 横浜 (46106) | 横浜 (46106) | できる |
| 相模原 | 八王子 (44112) | 横浜 (46106) | できない。28km 離れている |
| 熱海 | 網代 (50281) | 静岡 (50331) | できない。62km 離れている |

一致しない地点では、画面に「気温の比較は参考値」と出す。数字を並べて黙っていない。
降水確率は予報区単位なので、どの地点でも比較できる。

これ自体が1つの発見でもある。**気象庁の週間予報は相模原や熱海の気温を予報していない。**
一般の天気アプリがそこに出している気温は、離れた代表地点の予報か、何らかの内挿である。

### 気象庁の今日・明日の気温配列は順序が曖昧

短期予報（block 0）の `temps` は timeDefines の時刻と配列の対応が読み取れない。
09時と00時が交互に並び、今日の枠は同じ値が2つ入ることがある。
気温の比較には週間予報（block 1）だけを使い、短期予報からは降水確率と天気だけを取る。

### 真値は気象庁の日別値。自前で10分値を集計しない

当初はアメダスの10分値 JSON を日別に畳む設計だったが、次の2点で変更した。

- `bosai` のアメダス JSON は直近10日ほどしか遡れない。過去の予報を検証できない
- 自前集計は公式の日別値と必ずしも一致しない。「気象庁の記録と違う」数字が出る

`etrn` の日別値なら数十年遡れて、値は公表値そのもの。
これにより Previous Runs API で取った過去の予報を、初日から検証できるようになった。

### 平年値も公表値を使う

1991-2020 の日別平年値は気象庁が月ごとの表で公開している。
12リクエスト × 地点数で取れる。30年分の日別値を集めて自前で平均する必要はない。
公表値には観測所の移転補正などの統計処理が入っており、自前集計だと世間で言う「平年差」とずれる。

### 前向き検証は累積で1パスにする

学習し直すたびに XᵀX を先頭から計算し直すと、リードタイム17本 × 変数5個 × 地点4つ で数分かかる。
XᵀX と Xᵀy は行を足すだけで更新できるので、走査しながら累積する。
標準化した正規方程式は生のモーメントから解析的に組み立てられるので、精度も落ちない。
λ の候補も同じ累積から全部解ける。素朴な実装と 1e-8 まで一致することをテストで固定してある。

### 予測区間は必ず予報値を含める

アンサンブルの分位数は、そのモデル単体の分布。7モデルを合議して補正した予報値は、
その区間の外に出ることがある。「25.2〜29.2℃、予報は24.3℃」という表示は読む側にとって意味を成さない。
広がりだけを借りて、予報値の周りに付け直す。

### NDJSON は日付順に並んでいない

追記専用なので、バックフィルを後から走らせると「8月・9月の次に1月〜7月」という並びになる。
「直近N日」や「最後の観測日」が壊れるので、読んだ直後に日付で並べ直してから使う。
